# Руководство по обучению DQN-агента

## Почему 200 000 эпизодов не дали результата

Скорее всего сработало несколько факторов одновременно:

**1. Слишком разреженная финальная награда**  
Победа (+1000) — редкое событие. Случайный агент в 32×32 лабиринте с врагами
практически никогда не доберётся до выхода. Если в первые 10 000 эпизодов
агент ни разу не выиграл, нейросеть не получает сигнала, что победа вообще
достижима. BFS-награда (+10 за шаг к выходу) частично решает это, но только
если агент хотя бы иногда случайно движется в правильном направлении.

**2. Конфликтующие сигналы наград**  
- Исследование (+2.5) поощряет ходить по незнакомым клеткам  
- Штраф за атаку (−2.5) при отсутствии убийства → агент боится атаковать  
- Оба сигнала сопоставимы по величине и мешают выработать чёткую стратегию

**3. Размер карты vs. поле зрения**  
9×9 локального вида = 4.5 тайла в каждую сторону. Выход на 32×32 карте может
находиться в 20–25 тайлах. Агент его в принципе не видит из локального окна.
Два скалярных числа (dx_exit, dy_exit) должны компенсировать это, но MLP
без рекуррентной памяти плохо выстраивает долгосрочную стратегию по двум числам.

**4. Слишком медленное затухание ε**  
EPS_DECAY = 0.9925 → ε достигает 0.05 на эпизоде ~370.  
После этого 95% времени агент использует сеть. Если к эпизоду 370 сеть
ничему полезному не научилась (из-за отсутствия побед), агент «застревает»
в локальном минимуме своей плохой политики.

## На какой результат рассчитывать

| Условие | Ожидаемый сдвиг |
|---------|-----------------|
| Простая карта (16×16, 1–2 врага, без ям) | Первые победы: 500–2 000 эпизодов |
| Текущая карта (32×32, много врагов) | Первые победы: 5 000–30 000 эпизодов |
| Стабильные победы (win rate > 50%) | 30 000–100 000 эпизодов |
| Без структурных изменений в наградах | Возможно никогда |

**Ориентир**: простые Atari-игры (Pong, Breakout) обучаются за 1–5M шагов.
Ваша задача сложнее (исследование, редкая цель), но карта меньше. Реальный
горизонт при правильной настройке — 10–50M шагов ≈ 20 000–100 000 эпизодов
по 500 шагов.

## Метрики, на которые смотреть

### Главные (смотреть каждые 500 эпизодов)

| Метрика | Что означает | Тревожный сигнал |
|---------|-------------|-----------------|
| **win_rate** (% эпизодов с победой) | Прямой показатель успеха | = 0% после 10 000 эп. |
| **ep_reward (smoothed)** | Обще-положительный тренд | Плоский или падающий |
| **ep_steps (smoothed)** | Должен расти → агент живёт дольше | Всегда = 500 (timeout) |
| **loss** | Должна упасть и стабилизироваться | Постоянно растёт |
| **epsilon** | Ожидаемое затухание | Застрял на 1.0 (нет обучения) |

### Вспомогательные

```
avg_enemy_kills_per_ep   — агент учится убивать?
avg_bfs_reward_per_ep    — агент движется к выходу?
avg_hp_on_death          — агент выживает дольше со временем?
```

Добавьте в `train_log.csv` и `train.py` подсчёт этих метрик.

### Пример кода для win_rate в train.py

```python
wins = 0
window = 200  # считаем по последним 200 эпизодам
win_history = []

# В цикле по эпизодам:
won = done and env.last_state.get("player_hp", 0) > 0 and ep_reward > 900
win_history.append(int(won))
if len(win_history) > window:
    win_history.pop(0)
win_rate = sum(win_history) / len(win_history)

# Выводить каждые 100 эпизодов:
if ep % 100 == 0:
    print(f"  win_rate={win_rate:.1%}")
```

## Конкретные рекомендации

### 🔴 Критично (без этого не обучится)

**1. Curriculum learning — начни с простого**

Самое важное изменение. Добавьте параметры сложности в C# и постепенно
усложняйте:

```
Фаза 1 (эп. 0–2000):    карта 16×16, 0 врагов, нет ям
Фаза 2 (эп. 2000–6000):  карта 16×16, 1–2 врага
Фаза 3 (эп. 6000–15000): карта 24×24, 2–4 врага
Фаза 4 (15000+):          карта 32×32, полная сложность
```

Переход к следующей фазе — когда win_rate > 40% на текущей.

**2. Упрости функцию наград**

Текущая система слишком сложная. Предлагаемая минимальная версия:

```csharp
reward -= 0.1f;                          // штраф за время (меньше)
if (approached_exit) reward += 1.0f;    // BFS-приближение (меньше, чем +10)
if (done && hp > 0) reward += 50.0f;   // победа (не 1000 — слишком большой разброс)
if (hp <= 0) reward -= 10.0f;          // смерть
```

Большой разброс наград (от −10 до +1000) дестабилизирует обучение.
Нормализуйте максимум до ~100.

**3. Увеличь поле зрения до 15×15**

В game_interface.py: `VIEW = 15`, `HALF = 7`. OBS_SIZE → 225 + 4 = 229.
Обновите model.py: `OBS_SIZE = 229`.

При 15×15 агент видит выход, если он в радиусе 7 тайлов — намного лучше.

---

### 🟡 Важно (ускоряют обучение в 2–5×)

**4. Приоритизированный Experience Replay (PER)**

Редкие победы должны семплироваться чаще. В replay_buffer.py:

```python
# Простая версия: при добавлении победного перехода (done=True, reward>50)
# дублируй его в буфере 10 раз
if done and reward > 50:
    for _ in range(10):
        self.buffer.push(obs, action, reward, next_obs, done)
```

**5. Уменьши GAMMA для коротких горизонтов**

`GAMMA = 0.95` вместо 0.99. При 500 шагах и GAMMA=0.99 дисконтированная
награда на 400 шагов вперёд = 0.99^400 ≈ 0.018 — почти ноль.
С GAMMA=0.95: 0.95^100 ≈ 0.006 — агент реально учится думать на ~50 шагов.

**6. Double DQN (явный)**

В agent.py замените вычисление Q_next:

```python
# Текущий код (неявный Double DQN — уже лучше чем vanilla):
q_next = self.target(ns).max(dim=1).values

# Явный Double DQN — агент выбирает действие онлайн-сетью,
# оценивает целевой:
with torch.no_grad():
    best_actions = self.online(ns).argmax(dim=1, keepdim=True)
    q_next = self.target(ns).gather(1, best_actions).squeeze(1)
```

Это уменьшает overestimation Q-значений.

**7. Нормализуй награды онлайн**

```python
# В DQNAgent.__init__:
self._reward_running_std = 1.0
self._reward_alpha = 0.001  # скорость адаптации

# В store():
self._reward_running_std = (1 - self._reward_alpha) * self._reward_running_std \
                          + self._reward_alpha * abs(reward)
normalized_reward = reward / max(self._reward_running_std, 1.0)
self.buffer.push(obs, action, normalized_reward, next_obs, done)
```

### 🟢 Дополнительно (для продвинутой настройки)

**8. Добавь глобальную мини-карту в наблюдение**

Уменьши всю карту 32×32 до 8×8 (avg-pooling) и добавь как 64 доп. признака.
Это даст агенту глобальное представление о карте без увеличения размерности сети.

```python
# В _make_obs(): после построения local view
import numpy as np
full_map = np.array(map2d, dtype=np.float32) / ENTITY_MAX  # (32, 32)
mini_map = full_map.reshape(8, 4, 8, 4).mean(axis=(1, 3))  # (8, 8)
global_feat = mini_map.flatten()  # 64 признака
# OBS_SIZE становится 85 + 64 = 149
```

**9. Удали Idle из пространства действий**

Idle всегда штрафуется −10. Агент никогда не должен его выбирать.
Убрать из NUM_ACTIONS (7 действий вместо 8) — меньше пространство →
быстрее обучение.

**10. Увеличь буфер и батч**

